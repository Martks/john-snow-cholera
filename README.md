# Расследование вспышки холеры Джона Сноу

Небольшой учебный веб-проект по пространственному анализу вспышки холеры в Сохо (Лондон, 1854). Интерактивная карта позволяет сравнить расположение смертей, общественных водяных колонок и 120-метровых буферов вокруг них. Проект работает без QGIS, INTEGRO, npm и сборщика.

## Что есть на странице

- интерактивная карта Leaflet;
- современная подложка OpenStreetMap;
- геопривязанная тайловая карта Джона Сноу 1855 года как отдельная подложка;
- ползунок прозрачности исторической карты;
- слои `Deaths`, `Pumps` и `Buffers` с переключателем;
- масштабируемые по `count` точки смертей и всплывающие подсказки;
- карточка выбранной колонки и рейтинг по `death_sum`;
- легенда, аналитический вывод и кнопка `Reset view`;
- адаптивная компоновка для ноутбука и небольшого экрана.

## Как запустить локально

Из-за загрузки GeoJSON через `fetch()` страницу следует открывать через простой локальный сервер, а не двойным кликом по `index.html`.

1. Откройте терминал в папке проекта.
2. Запустите:

```bash
python -m http.server 8000
```

Если команда `python` не найдена в Windows, попробуйте:

```bash
py -m http.server 8000
```

3. Откройте в браузере [http://localhost:8000](http://localhost:8000).
4. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

Подключение к интернету требуется для библиотеки Leaflet, современной тайловой подложки и изображения исторической карты. Сами исследовательские GeoJSON-файлы хранятся локально.

## Как подставить реальные данные

Замените содержимое трёх файлов в папке `data`, сохранив имена файлов и систему координат WGS 84 (`EPSG:4326`, долгота/широта).

### `data/pumps.geojson`

Точечный `FeatureCollection`. Поддерживаемые свойства:

- `id` или `pump_id` — идентификатор колонки, если поле действительно уникально;
- `name` — название;
- `death_sum` — сумма смертей в буфере (необязательно).

В текущем наборе поле `Id` у всех восьми колонок равно `0`, поэтому оно не используется как ключ. Колонки пространственно сопоставляются с ближайшими центрами буферов, а уникальный `fid` буфера формирует интерфейсные обозначения `p1`–`p8`.

### `data/deaths.geojson`

Точечный `FeatureCollection`. Свойства:

- `Count`, `COUNT` или `count` — число смертей в точке;
- `address` — адрес (необязательно);
- `date` — дата (необязательно).

### `data/buffers.geojson`

Допускаются два варианта геометрии:

- `Point`: сайт сам рисует круг по `radius_m`;
- `Polygon` или `MultiPolygon`: готовая буферная геометрия из ГИС.

Приоритетные свойства статистики: `Count_sum`, `sum_Count` или `death_sum`. В текущих данных используется `Count_sum`, рассчитанное в QGIS; `NULL` означает отсутствие попавших в буфер смертей и отображается как `0`.

Если готового статистического поля нет, страница суммирует `Count` всех точек внутри исходного `Polygon`/`MultiPolygon`, включая точки на границе. Только при отсутствии полигональной геометрии используется расстояние 120 м от колонки.

Сейчас проект использует реальные файлы, подготовленные в QGIS: 8 колонок, 250 точек смертей и 8 полигональных буферов радиусом 120 м. Карта автоматически подбирает вид по границам загруженных слоёв; кнопка `Reset view` возвращает к этим границам.

## Публикация на GitHub Pages

1. Создайте новый GitHub repository.
2. Загрузите в корень репозитория `index.html`, `style.css`, `script.js`, `README.md` и папку `data` со всеми тремя GeoJSON-файлами.
3. Откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**.
5. Выберите branch `main`.
6. Выберите folder `/ (root)`.
7. Нажмите **Save**.
8. После завершения публикации откройте выданную GitHub публичную ссылку вида `https://username.github.io/repository/`.

`index.html` является точкой входа. Все локальные ресурсы подключены относительными путями, поэтому проект работает как из корня домена, так и из подпапки репозитория GitHub Pages. После публикации Python, QGIS, INTEGRO, backend и сборщик не требуются. Подключение к интернету необходимо для Leaflet и картографических тайлов.

## Данные и источники карты

- `data/*.geojson` — реальные данные исследования, подготовленные и экспортированные из QGIS: 8 колонок, 250 точек смертей и 8 буферов радиусом 120 м.
- Современная подложка: © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), стандартные растровые тайлы. Атрибуция также постоянно видна в правом нижнем углу карты.
- Историческая подложка: геопривязанный к Web Mercator тайловый слой [Snow Cholera Map Detailed](https://tiles.arcgis.com/tiles/j80Jz20at6Bi0thr/arcgis/rest/services/Snow_cholera_map_detailed/MapServer) — карта, созданная C. F. Cheffins для Джона Сноу и опубликованная в 1855 году по данным вспышки 1854 года. Сервис сообщает, что слой предназначен для учебного использования и основан на изображении из Wikimedia Commons. Тайлы работают без API-ключа; attribution постоянно видна на карте.
- Библиотека: [Leaflet 1.9.4](https://leafletjs.com/), подключена с официально указанного CDN с проверкой целостности файла.

Стандартные тайлы OpenStreetMap подходят для демонстрационного учебного проекта с умеренным трафиком. При массовом использовании следует ознакомиться с актуальной [политикой использования тайлов](https://operations.osmfoundation.org/policies/tiles/).

## Аналитическая оговорка

В QGIS максимальная сумма в одном из буферов составляла 257, а в INTEGRO для `p1` — 212. Это расхождение не обязательно является ошибкой: на результат могут влиять точные входные данные, система координат, параметры буфера, правила включения объектов на границе и особенности реализации пространственных операций.
